# RAW Select — XXL-Audit (read-only)

**Datum:** 2026-08-02 · **Version:** 1.4 (Constants + build_app.sh synchron) · **Basis:** Commit `8fe3713`, Git sauber
**Methode:** 5 unabhängige Tiefen-Analysen (Performance, Stabilität/Datenverlust, UX/Tastatur, Architektur, Features/Workflow) + eigene Messungen an 35 echten Sony-ARWs (13–47 MB). Nichts am Produktcode geändert.

> Jede Aussage ist mit `Datei:Zeile`, einem Messwert oder als **THEORETISCH** gekennzeichnet. „REAL" = im Code/Messung belegt.

---

## A. Executive Summary

**Zustand:** Überdurchschnittlich sauberes, reifes Ein-Personen-Projekt (48 Dateien, ~8.200 Zeilen, 61 Commits seit 07.07.2026). Baseline grün: `swift build` 0,22 s, 30 Selbsttest-Checks bestanden. Der Kern-Loop (Scan → flackerfreie Vorschau → 1–9 markieren → Filter → Kopieren/Export → Lightroom-Bridge) funktioniert Ende-zu-Ende und ist ungewöhnlich gut gegen Datenverlust gehärtet.

**Grösste Stärken:** Kein Decode/IO auf dem Main-Thread; Browsing entwickelt nie das RAW (nur eingebettetes JPEG), volle RAW-Entwicklung nur beim Zoom, ein Bild zur Zeit; synchroner Cache-Read → kein Ladeflackern; O(1)-Navigation; globaler NSEvent-Key-Monitor (kein SwiftUI-Fokusproblem); Auto-Advance; teuer erkaufte Bridge-/Kalibrier-Fakten sind konzentriert gekapselt und mit Selbsttests als Regression abgesichert.

**Grösste Probleme:**
1. **KRITISCH — Datenverlust am Session-Ende:** kein synchroner Flush beim Beenden; die letzte Markierung vor ⌘Q kann verloren gehen.
2. **HOCH — Loupe-Prefetch flutet die Queue** (nicht abbrechbar, sehr breites Fenster) + fehlendes In-Flight-Dedup → Stottern beim schnellen Scrubben, Doppel-Decodes.
3. **HOCH — Culling-Tempo lässt Sekunden liegen:** kein ↑/↓ im Raster, Filter nur per Maus, kein Sprung zum nächsten Markierten/Unmarkierten, Schärfe-Check kostet 2 Schritte.
4. **HOCH — Sport-Kernlücke:** Zoom-Ausschnitt bleibt beim Blättern nicht erhalten; kein Vergleichs-/Fokus-Peaking-Modus; kein Reject→Löschen-Flow.

**Höchste Risiken:** Datenverlust am Session-Ende (real, Normalfall); unsichtbare Speicher-Fehler im Fokus-Modus; bekannter Blocker Lightroom-Katalog-Verschmutzung (682 Geister, extern).

**Grösste Chancen:** Fast alle Tempo-Lücken sind **additive Shortcuts** im bestehenden `handle()`-Switch — wenig Aufwand, hoher Nutzen. Der Prefetch ist der einzige echte Performance-Umbau.

**Gesamteinschätzung:** Produktiv tragfähig. Vor allem anderen gehört das Session-Ende datensicher gemacht; danach zahlt sich Tempo (Tastatur + Prefetch) und der Sport-Culling-Kern (Zoom-halten, Reject, Vergleich) am stärksten aus. Der In-App-Develop-Editor ist der einzige Bereich mit Feature-Creep-Risiko gegenüber „Adobe-delegiert".

## B. Realer Workflow

**Heutiger Ablauf:** Ordner/SD öffnen (Sidebar/Baum/⌘O/Drag&Drop) → Scan mit Live-Zähler → Grid → Return in die Loupe → mit ←/→ steppen, 1–9 markieren (Auto-Advance) → Filter per Maus → Auswahl kopieren/verschieben oder Export an Lightroom.

**Engpässe (Zeit pro Bild):**
- Filter nur per Maus (`FilterBar.swift`) — jeder Wechsel „nur Unmarkierte" reisst die Hand von der Tastatur.
- Kein Sprung zum nächsten Markierten/Unmarkierten → der zweite Culling-Pass ist sequenzielles Dauer-Steppen.
- Kein ↑/↓ im Raster (`AppState.swift:717-722`) → Grid nur horizontal bedienbar.
- Schärfe-Check = Return→Z (Zoom nur in der Loupe, `AppState.swift:756`).
- Zoom-Ausschnitt springt bei jedem Bildwechsel auf „Einpassen" zurück (`AppState.swift:25`, `LoupeView.swift:135`) → Serien-Schärfevergleich zäh.

**Unnötige Schritte:** Nach dem Öffnen landet man im Grid statt in der Loupe (eine Return-Taste pro Ordner). Sortierung und Thumbnail-Grösse sind doppelt bedienbar (Toolbar + Settings + Statusleiste).

**Ideale Zukunftsversion:** Öffnen → sofort Loupe → einhändig durchsteppen, markieren, per Taste filtern und zum nächsten Offenen springen; im Zoom über eine Serie blättern, ohne den Ausschnitt zu verlieren; Ausschuss per Reject-Taste sammeln und am Ende löschen.

**Zeitersparnis (geschätzt, nicht gemessen):** Filter-Tasten + „nächstes Unmarkiertes" + ↑/↓ sparen im zweiten Durchgang über 1.000 Bilder plausibel mehrere Minuten; Zoom-halten spart bei jeder Serie mehrere Sekunden.

## C. Performance-Report

**Messwerte (eigene, an echten ARWs):**
- Baseline-Build 0,22 s; `--rawcheck` je RAW ~0,69 s real (inkl. Prozessstart).
- **RAW-Dekodierbarkeit gemischt:** 33-MP-ARWs (neuere Sony, wahrsch. lossless-compressed) → *macOS kann nicht nativ entwickeln* → Zoom nutzt das voll­auflösende eingebettete JPEG (4672×7008). Kleinere/ältere ARWs → native Entwicklung OK. Für die Anzeige unkritisch (Full-Res-JPEG), für die Develop-Vorschau-Genauigkeit relevant (rechnet dann auf verarbeitetem JPEG statt linearem RAW).
- **Thumbnail-Cache rein im RAM** (`NSCache`, `countLimit=1200`, `totalCostLimit≈1 GB`, `ThumbnailLoader.swift:24-25`). **Kein Platten-Cache** → jeder App-Start dekodiert alles neu (Cold-Start). Da pro Foto mehrere Grössen gecacht werden, hält das Countlimit effektiv nur ~240–300 Fotos vollständig warm.

**Engpässe (Ursache → Wirkung):**
1. **Prefetch-Flut, nicht abbrechbar** (`ThumbnailLoader.prefetch` :34-51 hat keinen Cancel-Pfad; `prefetchAroundCurrent` :322-355 feuert bei jedem `currentID`-Wechsel ein Fenster von ~45 vor / ~22 zurück). Schnelles Scrubben/Sprünge sammeln veraltete Decodes an, die nie angezeigt werden → verschwendete CPU/IO + Cache-Verdrängung. **REAL.**
2. **Kein In-Flight-Dedup in `thumbnail(...)`** (`:96-114`, prüft `inFlight` nicht) → dasselbe Bild wird in der Übergangszone Prefetch↔Anzeige doppelt dekodiert. **REAL.**
3. **`prefetchAroundCurrent` läuft ganz auf dem Main-Actor, pro Tastendruck, ohne Debounce** (~150 Iterationen bei „Ausgewogen"). Bei gehaltener Pfeiltaste spürbar. **REAL.**
4. **Filmstrip-Zelle dekodiert eine „sharp"-Stufe kleiner als tiny** (`ThumbnailCell.swift:76`, 143 px < 160 px) → 1 überflüssiger Decode pro Zelle. **REAL.**
5. `DateFormatter` pro Zellen-Render (`ThumbnailCell.swift:85-88`, nur bei aktivem Datum). **REAL, klein.**
6. `hslCube` pro `apply()` neu gebaut (4096 Einträge, `DevelopEngine.swift:171-232`) — nur im Editor, nicht im Culling-Pfad. **REAL.**

**Schnelle Verbesserungen:** In-Flight-Dedup in `thumbnail`; Prefetch-Fenster verkleinern/abbrechbar machen; Filmstrip-„sharp" überspringen wenn ≤ tiny; statischer DateFormatter.
**Grössere:** Prefetch-Handles halten und beim Fenstersprung canceln; optionaler Platten-Thumbnail-Cache gegen Cold-Start; `countLimit` grössen-bewusst anheben.
**Zielwerte (zu definieren via Instruments/os_signpost):** 0 Decodes für nie angezeigte Indizes beim Scrub über 1.000 ARW; keine Doppel-Decodes desselben Keys innerhalb 1 s beim Loupe-Browsing.

**Gut gelöst (nicht anfassen):** kein Main-Thread-Decode; embedded-JPEG statt RAW-Entwicklung beim Browsen; synchroner Cache-Read; korrekter Grid-Cancel via `.task(id:)`; genau ein Full-Res-RAW im Speicher; NSCache-Kostenlimit; keine Retain-Cycles gefunden.

## D. Stabilitäts- & Sicherheitsreport

**Fixes aus `8fe3713` verifiziert — halten alle:** Scope-Merge (`SessionStore.save` :104-134), atomares `place()` (`LightroomExportService.swift:475-490`), defekte RAWs killen den Batch nicht (:101-140), Quarantäne unlesbarer Session-Dateien (:107-116,153-159), alle Writes `.atomic`. Durch Selbsttest als Regression abgedeckt.

**Verbleibende/neue Risiken:**
1. **KRITISCH (REAL) — Kein Flush beim Beenden.** `persistState()` schreibt async in `Task { await SessionWriter… }` (`AppState.swift:457-463`); es gibt **kein** `applicationWillTerminate`/`scenePhase`/`deinit`-Flush (`RAWSelectApp.swift:71-84`, `applicationShouldTerminateAfterLastWindowClosed → true`). Letztes Bild bewerten + sofort ⌘Q/Fenster schliessen → der offene Write wird verworfen → **letzte Markierung nie gespeichert.** Fix: `applicationWillTerminate`/`applicationShouldTerminate(.terminateLater)` → `persistStateNow()` synchron.
2. **PROBLEMATISCH (REAL, Zusage stimmt nicht) — Write-Reihenfolge nicht garantiert.** Der `SessionWriter`-Kommentar (`SessionStore.swift:136-138`) verspricht „letzte Taste gewinnt"; frei geschedulte Top-Level-`Task`s erreichen den Actor aber nicht garantiert in Erzeugungsreihenfolge. Ein verspäteter älterer Snapshot (scope = ganzer Ordner) überschreibt den neueren komplett. Selbstheilend beim nächsten Tastendruck — **ausser beim letzten Write vor dem Beenden** (fällt mit #1 zusammen). Fix: Sequenz-/Generation-Nummer im Actor, veraltete Writes verwerfen.
3. **PROBLEMATISCH (REAL) — Speicher-Fehler praktisch unsichtbar.** `.failed`/`.quarantined` landen nur in `statusMessage` (`AppState.swift:441-451`), das der nächste Tastendruck überschreibt — und die StatusBar ist im **Fokus-Modus ausgeblendet** (`DetailView.swift:10`). Platte voll / Rechte weg mitten in der Session → unbemerktes Weitermarkieren ins Leere. Fix: `.error`-Toast (existiert) statt/zusätzlich zu `statusMessage`.
4. **AKZEPTABEL/THEORETISCH — Quarantäne-Fallthrough.** Scheitert `quarantine()`s `moveItem` (`SessionStore.swift:113-116,157`), schreibt der Code danach doch `.atomic` über die unlesbare Datei → „nie überschreiben"-Garantie verletzt. Randfall, nicht getestet.
5. **AKZEPTABEL/THEORETISCH — Fingerprint-Kollision.** Karten ohne Volume-UUID werden über `name-capacity-creationDate` identifiziert (`FolderIdentity.swift:33-37`); fehlt zusätzlich das Erstellungsdatum, kollidieren zwei baugleiche „Untitled"-Karten → Marks bluten. Best-Effort, dokumentiert.

**Weitere Beobachtungen:** Nur 1 `NSLog`, kein Crash-Handler, kein State-Restore — Datensicherheit hängt voll an der Pro-Aktion-Persistenz (die grundsätzlich solide ist). Update-Check gegen `levinvfx/RAWSelect` verifiziert **HTTP 200** (funktioniert, kein stiller Fehler).

**Extern/bekannt:** Lightroom-**Katalog-Verschmutzung** (682 Geister-Fotos) bleibt der Blocker vor Verbreitung an Fremde — SDK kann nicht entfernen, stabiler-Pfad-Trick gemessen widerlegt (siehe Memory `rawselect-katalog-verschmutzung`).

**Solide gelöst:** SD-Auswurf mitten in der Session (Marks auf interner Platte, `persistKey` vorab); In-flight-Write nach Ordnerwechsel landet korrekt in A's Datei; Undo pro Ordner isoliert; Copy/Move prüft `fileExists` pro Datei, bricht nie ab; Move von externen Volumes gesperrt.

**Test-Lücken:** async `persistState`/`SessionWriter`-Pfad, Write-Reihenfolge, Flush-beim-Beenden, Quarantäne-Move-Fehler — nicht abgedeckt.

## M. Automations-Empfehlung

**Empfehlung: sequenzieller, persistenter Autopilot** — genau das vereinfachte LevinCut-Muster (Job → Implementierung → Self-Check → unabhängiges Review → bei REWORK gezielter Repair-Job → Merge → **Gate = `swift build` + `--selftest` grün** → DONE → nächster Job), mit fortsetzbarem Zustand und Terminal-Live-Anzeige. Grund: viele Befunde fassen dieselben zentralen Dateien an (`AppState`, `ThumbnailLoader`, `SessionStore`) → echte Parallelität würde ständig kollidieren, und bei einer produktiven App zählt Zuverlässigkeit mehr als Tempo. **Maximal zwei parallele Jobs** nur für nachweislich getrennte Bereiche (z. B. „toten Code entfernen" ∥ „Filmstrip-/DateFormatter-Kleinkram"). Katalog-Verschmutzung (Bridge) ist ein separater, isolierter Job. **Noch nicht starten** — erst nach Freigabe der Roadmap.
